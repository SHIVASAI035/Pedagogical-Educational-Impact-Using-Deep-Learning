# REST API Reference

Base URL in development: `http://127.0.0.1:5000/api`

All request and response bodies are JSON. The frontend proxies `/api` to the
backend through Vite, so browser code can use relative URLs.

## Authentication

Protected endpoints require a JWT:

```
Authorization: Bearer <access_token>
```

Tokens are issued by `POST /api/auth/login` and `POST /api/auth/register` and
expire after 12 hours by default (`JWT_ACCESS_TOKEN_EXPIRES_HOURS`).

### Error format

```json
{ "error": "forbidden", "message": "You do not have access to this student's records." }
```

| Status | Meaning |
|---|---|
| 400 | Malformed request |
| 401 | Missing or expired token |
| 403 | Authenticated but not allowed |
| 404 | Resource not found |
| 409 | Duplicate email / roll number / code |
| 422 | Validation failure |
| 503 | Model not trained |

## Roles and access rules

| Role | Can do |
|---|---|
| `admin` | Everything: users, classes, subjects, all analytics, dataset and model management, all reports |
| `teacher` | Own profile, assigned classes/students, marks, attendance, assignments, teaching sessions, classroom observations, learning activity, feedback summaries for **own** teacher id, own analytics and recommendations |
| `student` | Own profile, own marks/attendance/assignments, own analytics and predictions, submit feedback, own recommendations |

Students can never read another student's records. Teachers can only read
students in classes they teach or lead, and only their own feedback summaries.

## Authentication

### `POST /api/auth/register`
Public for students. Creating a teacher or admin requires an admin token.

```json
{
  "full_name": "New Student",
  "email": "new@school.edu",
  "password": "Password123",
  "role": "student",
  "roll_number": "S2001",
  "class_id": 1,
  "guardian_name": "Guardian"
}
```

Response `201`:

```json
{ "access_token": "<jwt>", "user": { "id": 1, "email": "...", "role": "student", "student_id": 10 } }
```

### `POST /api/auth/login`
```json
{ "email": "admin@school.edu", "password": "Admin@12345" }
```

### `GET /api/auth/profile`
Returns the current user, including `student_id` or `teacher_id` when present.

### `PUT /api/auth/profile`
Updates `full_name`; students may update `guardian_name`; teachers may update
`department` and `specialization`.

### `POST /api/auth/change-password`
```json
{ "current_password": "...", "new_password": "..." }
```

## Academic records

### `GET /api/academics/records?student_id=&subject_id=&page=&per_page=`
Role-filtered automatically. Teachers see only their subjects unless they
request an accessible student.

### `POST /api/academics/records` — admin, teacher
```json
{
  "student_id": 1,
  "subject_id": 2,
  "exam_name": "Midterm",
  "marks_obtained": 78,
  "max_marks": 100,
  "exam_date": "2026-02-10"
}
```

Teachers can only record marks for subjects they teach. `marks_obtained` may not
exceed `max_marks`.

### `PUT /api/academics/records/{id}`, `DELETE /api/academics/records/{id}`
Admin or the subject's teacher.

## Attendance

### `GET /api/academics/attendance?student_id=&subject_id=&date_from=&date_to=`
Students always receive their own records.

### `POST /api/academics/attendance` — admin, teacher
Single row or bulk:

```json
{
  "records": [
    { "student_id": 1, "subject_id": 2, "date": "2026-02-10", "status": "present" },
    { "student_id": 2, "subject_id": 2, "date": "2026-02-10", "status": "absent" }
  ]
}
```

Response: `{ "created": 2, "updated": 0 }`. Existing
(student, subject, date) rows are updated rather than duplicated.

### `PUT /api/academics/attendance/{id}`
Update `status` to `present`, `absent` or `late`.

## Teaching sessions and classroom observations

These are the records behind the teacher analytics and the impact module. They
are written by teachers (and admins) and read by both.

### `GET /api/teaching/methodologies`
Returns the controlled methodology taxonomy used by every form and chart:

```json
[
  { "name": "Lecture", "description": "Teacher-led explanation with minimal student activity." },
  { "name": "Demonstration", "description": "Teacher shows a process or worked example step by step." }
]
```

The six values are `Lecture`, `Demonstration`, `Collaborative Learning`,
`Flipped Classroom`, `Project Based Learning` and `Discussion`. Any other value
is rejected with `422`, so the comparison charts never contain free-text
variants.

### `GET /api/teaching/sessions?teacher_id=&subject_id=&page=&per_page=`
Teachers always receive only their own sessions; admins may filter by teacher.

### `POST /api/teaching/sessions` — admin, teacher
```json
{
  "subject_id": 4,
  "methodology": "Discussion",
  "date_used": "2026-02-10",
  "duration_minutes": 50,
  "description": "Structured debate on renewable energy."
}
```

Rules:
- A teacher may only log for themselves; passing another `teacher_id` returns `403`.
- `subject_id` must be a subject the teacher is assigned to, otherwise `422`.
- `subject_id` is optional (a session can be logged without a subject).

`PUT /api/teaching/sessions/{id}` and `DELETE /api/teaching/sessions/{id}` are
available to the owning teacher or an admin.

### `GET /api/teaching/observations?teacher_id=&page=&per_page=`
### `POST /api/teaching/observations` — admin, teacher

```json
{
  "subject_id": 4,
  "methodology": "Discussion",
  "observation_date": "2026-02-10",
  "interaction_score": 8,
  "clarity_score": 7.5,
  "engagement_score": 8,
  "practical_examples_score": 7,
  "material_usage_score": 6,
  "observer_notes": "Strong questioning; more wait time needed."
}
```

All five scores are 0–10. When `class_id` is omitted it is inferred from the
subject. Observations are stored with `observer_id` set to the authenticated
user. `PUT` and `DELETE` follow the same ownership rules as sessions.

Students receive `403` on every route in this section.

## Deep learning

| Method | Path | Roles | Purpose |
|---|---|---|---|
| GET | `/api/dl/status` | authenticated | Ready flag, version, feature order |
| GET | `/api/dl/metrics` | authenticated | Metrics JSON (503 if not trained) |
| POST | `/api/dl/train` | admin | Train synchronously, return metrics |
| POST | `/api/dl/predict/{student_id}` | admin, teacher, owner | Predict and store |
| POST | `/api/dl/predict/me` | student | Predict own score |
| GET | `/api/dl/predictions?student_id=` | role-filtered | Prediction history |

Prediction response:

```json
{
  "predicted_score": 71.72,
  "risk_level": "low",
  "model_version": "student-ann-v1",
  "features_used": { "attendance_pct": 93.18, "...": 0 },
  "confidence": "high",
  "completeness": 1.0,
  "prediction_id": 55,
  "created_at": "2026-02-10T10:00:00",
  "student_id": 1,
  "student_name": "Student 1001",
  "note": "Prediction from a model trained on synthetic data..."
}
```

Risk bands: `< 50` high, `50–64.99` moderate, `>= 65` low.

## Analytics

| Method | Path | Roles | Purpose |
|---|---|---|---|
| GET | `/api/analytics/student/me` | student | Own full dashboard payload |
| GET | `/api/analytics/student/{id}` | admin, teacher, owner | Student dashboard payload |
| GET | `/api/analytics/teacher/me` | teacher | Own multi-indicator analytics |
| GET | `/api/analytics/teacher/{id}` | admin, owner | Teacher analytics |
| GET | `/api/analytics/impact` | admin, teacher | Correlations, methodology comparison, engagement, clusters, insights |
| GET | `/api/analytics/methodology-comparison` | admin, teacher | Methodology table + ANOVA |
| GET | `/api/analytics/engagement` | admin, teacher | Engagement by methodology/class |

Teacher analytics deliberately contains **no composite score**. It returns
indicator values, benchmarks, data sufficiency, caveats and anonymised comments.

Impact analytics contains a `causality_statement` and `limitations` array that
the UI displays verbatim.

## Feedback and NLP

### `POST /api/feedback` — student
```json
{
  "teacher_id": 2,
  "subject_id": 4,
  "clarity_rating": 4,
  "interaction_rating": 4,
  "methodology_rating": 5,
  "practical_rating": 4,
  "difficulty_rating": 3,
  "overall_rating": 4,
  "comments": "Clear explanations and useful practical examples.",
  "is_anonymous": true
}
```

Response includes the stored feedback and the NLP analysis:

```json
{
  "analysis": {
    "label": "positive",
    "score": 0.62,
    "text_score": 0.71,
    "rating_score": 0.5,
    "keywords": ["clear", "useful", "practical"],
    "aspects": { "clarity": 0.71, "practical": 0.71 },
    "method": "lexicon+ratings-fusion-v1"
  }
}
```

### `GET /api/feedback/mine` — student
Own feedback history.

### `GET /api/feedback/summary?teacher_id=`
Admin, or the teacher themselves. Aggregate ratings, sentiment counts and top
keywords. **Never returns student identity.**

### `GET /api/feedback/nlp?teacher_id=`
Aspect sentiment, keywords, method and limitations.

### `GET /api/feedback/recent?teacher_id=`
Up to 20 anonymised comments.

## Pagination

Endpoints returning lists of records use:

```json
{
  "items": [],
  "total": 54,
  "page": 1,
  "pages": 2,
  "per_page": 50
}
```

`per_page` is capped at 100.
